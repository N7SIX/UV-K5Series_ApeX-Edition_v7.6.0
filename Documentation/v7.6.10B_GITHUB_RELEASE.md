## What's New

Bug-fix release: full RX (receive) implementation audit of **simplex and repeater operation**, seven
fixes. Complete report: [`Documentation/RX_SIMPLEX_REPEATER_AUDIT.md`](Documentation/RX_SIMPLEX_REPEATER_AUDIT.md).

### 1. Airband no longer "poisons" the next channel (RX-1)
- **Problem:** after listening to the airband, selecting an FM memory channel could keep the radio in **AM**: distorted audio, no CTCSS/DCS decoding and **PTT refused** — the wrong mode was also saved to EEPROM.
- **Cause:** the v7.6.6 airband rule was evaluated in the channel/VFO reload path against the **previous** RX frequency.
- **Fix:** the stored mode is kept as-is there and the airband rule is applied once, after the new frequency is final. Airband still always resolves to AM.

### 2. Transmit always follows the displayed frequency (RX-2, RX-3)
- **RX-3 — no more "old frequency" PTT window:** stepping or entering a frequency retunes RX instantly, but the TX frequency was only refreshed by the deferred save cycle (up to ~500 ms). Keying up inside that window transmitted on the **previous** frequency; TX is now re-derived at PTT time, *before* the band-plan check.
- **RX-2 — impossible offsets are refused, not wrapped:** an offset larger than the RX frequency (e.g. 145.000 MHz with a "−" shift of 999.999 MHz) used to wrap the internal TX frequency to ~42 GHz. It is now marked invalid and the radio just beeps "TX disabled" instead.

### 3. Repeater operation hardened (RX-4, RX-7)
- **RX-4 — stored repeater shift survives the airband:** the "no shift on airband" rule is applied at run time instead of erasing the saved direction, so a programmed "+600 kHz" (or any split) is no longer lost after tuning through 108–137 MHz.
- **RX-7 — repeater tail-tone elimination after a timeout:** when a transmission ends by the **TOT** (time-out timer), releasing PTT now honours `RP STE` exactly like a normal release, so the repeater tail is suppressed instead of being heard.

### 4. Dual-watch squelch and TX-lock icon (RX-5, RX-6)
- **RX-5:** changing `Sql` (menu or F + ▲/▼) now refreshes **both** VFOs, so the second dual-watch VFO no longer keeps the old thresholds.
- **RX-6:** the padlock icon is decided by the actual **TX** frequency, so it appears only when TX is really blocked (cross-band offsets showed a wrong icon before).

## Verification

- Host harness (real functions extracted from `radio/radio.c`): **19/19 checks pass** — RX-1/-2/-3/-4 behaviour plus regression cases (±600 kHz, +5 MHz, simplex, 350EN on/off).
- Build: `-Oz -Wall -Wextra -Werror`, LTO + `--gc-sections` — **0 warnings / 0 errors** in both the release define set and the plain Makefile defaults.
- FLASH: **+24 bytes** for the whole patch set, `.bss` unchanged → **no RAM cost**.
- Recommended bench pass (see audit report Appendix A): airband → memory channel stays FM and can TX; step + immediate PTT transmits on the displayed frequency; nonsense offset shows "TX disabled"; stored shift survives an airband round-trip; `Sql` applies to both VFOs; padlock matches real TX capability; TOT + `RP STE` suppresses the tail.
