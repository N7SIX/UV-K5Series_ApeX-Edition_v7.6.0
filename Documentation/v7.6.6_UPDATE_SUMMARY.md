# Version Update Summary - v7.6.6

Date: May 04, 2026
Firmware build: v7.6.6 ApeX Edition
Focus: SysInf multi-page implementation, scan-range defaults, and Docker build workflow usability
Status: Implemented and validated

Update addendum (May 04, 2026): Airband AM modulation enforcement and validation

## Summary
This v7.6.6 update finalizes the SysInf menu behavior for K5 with a 3-page display flow, restores scan-range defaults expected in ApeX builds, and improves Docker build script reliability/usability (POSIX shell compatibility and case-insensitive `ApeX`/`apex` command handling). Build output was revalidated successfully after these changes.

## Getting Started
- UVTools: https://n7six.github.io/UVTools/

## Key Changes
1. SysInf menu converted to 3-page behavior (K1-aligned implementation)
- Added menu limits so `MENU_VOL` uses submenu index pages `0..2`.
- Added default SysInf entry page (`gSubMenuSelection = 0`) when opening SysInf.
- Reworked SysInf render path in menu UI:
- Page 1: firmware identity (`AUTHOR_STRING_2`, `VERSION_STRING_2`, `Edition`)
- Page 2: battery voltage + battery percent
- Page 3: battery health + remaining capacity
- Added left/right navigation indicators (`<` and `>`).

2. Scan-range defaults aligned for v7.6.6
- Enabled scan ranges by default in build configuration.
- Enabled scan ranges in shared app header defaults.

3. Docker build script modernization and command usability
- Replaced non-POSIX `[[ ... ]]` platform detection with POSIX `case` logic.
- Added normalized command parsing so both `ApeX` and `apex` are accepted.
- Moved Docker clean/rebuild into a `prepare_build` path executed only for actual build commands.
- Added centralized usage output helper.

4. Packaging and file-format updates
- Rebuilt v7.6.6 firmware artifacts after integrating menu/build changes.
- Normalized line endings in auxiliary Windows build helper content where modified during update workflow.

5. Airband AM investigation and modulation lock fix
- Root cause found: modulation could drift from AM on airband after EEPROM reload or user mode toggles.
- Implemented shared helpers to enforce airband modulation by frequency range.
- Enforced clamp points:
	- VFO initialization
	- Channel/VFO reload path
	- Post-frequency normalization in channel configure path
	- Menu mode selection and demod-cycle shortcut action
- Fixed an impossible condition in airband TX-offset handling where the range check used duplicated upper bounds.
- Verified build success after fix: `./compile-with-docker.sh ApeX`

## Validation
- Build: `./compile-with-docker.sh ApeX` (success)
- Diagnostics: firmware links and packs successfully; no unresolved compile errors in modified paths
- Notes: last successful build reported:
- FLASH: `60108 / 65536` (`91.72%`)
- RAM: `5256 / 8192` (`64.16%`)

## Impact
- SysInf now matches requested K1-style usability with deterministic page navigation and clearer battery/system information grouping.
- Scan-range behavior is enabled by default again for expected scanning workflows.
- Build workflow is less error-prone on Linux/`sh` and no longer rejects lowercase `apex`.
- Airband now behaves deterministically as AM-only in `108.000-136.999 MHz`.
- FM/USB selection attempts on airband are automatically normalized back to AM.
