## What's New

Bug-fix release: **two receive-path stability fixes**. Both were found by tracing a
reported symptom — *on a UHF memory channel with a repeater offset, the RX audio
opens and closes intermittently, while spurious DTMF digits appear on screen at the
same time* — back through the tone and AGC state machines.

If you have been living with that, this release is for you. Neither defect exists
upstream; both were introduced by this edition's spectrum and DTMF work.

### 1. Spurious DTMF digits and choppy RX on repeater channels (RX-10)

- **Problem:** the DTMF decoder was **permanently armed** — the `D Live = off` menu
  setting could never actually take effect. Because the DTMF decoder is a tone
  detector sharing the CTCSS/tail filter bank, ordinary voice and noise energy on a
  UHF repeater carrier could raise false "code found" interrupts. Those were latched
  as real digits (hence the phantom digits on screen), and the same tone energy
  disturbed the tail/squelch detector, so the audio opened and closed.
- **Cause:** `RADIO_SetupRegisters()` enabled the DTMF decoder and set its interrupt
  mask bit **unconditionally** on every RX reconfigure. Turning `D Live` off called
  `BK4819_DisableDTMF()`, but the same menu handler then requested a VFO
  reconfigure, which re-enabled it within milliseconds.
- **Fix:** the receiver now honours `D Live` and leaves the DTMF interrupt out of the
  mask when the decoder is off, so a false digit cannot be latched at all.
  **DTMF transmit is unaffected** — PTT-ID and DTMF-ID still key exactly as before.

### 2. RX could stay silent or the S-meter read wrong after the spectrum view (RX-11)

- **Problem:** after using the spectrum analyser, the radio could be left with the
  AGC disabled or a stale gain table, so audio stayed silent or the S-meter was
  wrong — until some unrelated action happened to change the modulation.
- **Cause:** `RADIO_SetupAGC()` skipped its register writes whenever its arguments
  matched the previous call, via a private static cache. That assumption was wrong:
  the spectrum code writes the AGC gain table directly, and the cache key never
  changed on the spectrum path at all. `RestoreRegisters()` restores the AGC enable
  bit but not the gain table, so the bad state survived leaving the spectrum.
- **Fix:** the unsound cache is gone — the AGC is now programmed from the requested
  state every time. The spectrum's listen mode freezes the AGC while tuning to a
  peak and restores it afterwards, and the register-menu AGC lock does what it says.

### 3. Local build helper repaired (tooling, not firmware)

`tools/build_k5.ps1` had drifted out of sync with the Makefile and had not produced
a valid link since the spectrum work landed — it referenced a file that does not
exist, omitted three sources, and omitted the spectrum define entirely, so the size
it printed was meaningless. It now derives the version and every feature toggle from
the Makefile at run time.

> **Note:** a local (non-Docker) toolchain produces an image ~620 B **larger** for
> identical code, which can exceed the flash budget for a configuration that is
> perfectly fine in the release build. Always take release figures from
> `./compile-with-docker.sh ApeX`.

## Verification

- Build: `-Oz -Wall -Wextra -Werror`, LTO + `--gc-sections` — **0 warnings / 0 errors**.
- Byte-exact release measurements, each taken on the same image for a like-for-like
  comparison:

  | Build | FLASH | RAM | free |
  |---|---|---|---|
  | v7.6.10B | 61,364 B | 3,564 B | 76 B |
  | v7.6.10C | **61,348 B** | **3,560 B** | **92 B** |

  Both fixes *reduce* size: net **−16 B FLASH, −4 B RAM** against v7.6.10B.
- **Bench pass recommended.** These fixes are code-verified and build-verified but
  not yet confirmed on hardware. On the channel that showed the fault, please check:
  1. spurious DTMF digits stop appearing — or keep appearing if that repeater really
     does carry DTMF, in which case the digits are real and the UHF squelch table is
     the next thing to look at;
  2. entering and leaving the spectrum view leaves audio and the S-meter correct;
  3. PTT-ID / DTMF-ID still key correctly.
